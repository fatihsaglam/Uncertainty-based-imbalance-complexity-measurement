# Uncertainty-based complexity measures for class imbalance

Code and results for the paper *Measuring class imbalance complexity through classifier uncertainty: when does oversampling pay off?* (Fatih Sağlam, submitted to Knowledge-Based Systems).

The paper proposes classifier-aware complexity measures for class imbalance. They split each training case's out-of-bag error into an aleatoric part (label noise and overlap) and an epistemic part (disagreement between the model and a class-balanced local posterior). The main measure is the soft-split epistemic measure with a class-balanced 15-neighbour vote. The repository also contains the analysis of whether the measure tells when oversampling pays off.

## Contents

| Path | What it is |
|---|---|
| `R/` | Library code: classifiers, resamplers, the proposed complexity measures (`R/complexity/complexity_proposed.R`), literature complexity measures (`R/complexity/complexity_literature.R`) and the data simulator |
| `global.R` | Loads packages and sources `R/` |
| `run.R` | Simulation: five data families, six imbalance ratios, seven classifiers; writes the raw results to `results/sim_cxgain_*` |
| `run_real.R` | Real data: 5-fold cross-validation with and without SMOTE/ROS and the complexity measures on each training fold; writes `results/real_*` |
| `data/datasets_binary.rds` | Binary imbalanced datasets from the UCI and KEEL repositories (30 are selected by `run_real.R`; the selection is saved in `results/real_selection.csv`) |
| `analiz_korelasyon.R` | Simulation analysis: correlation with the performance lost to imbalance, added value over IR |
| `analiz_real.R` | Real-data analysis: correlation with the gain from resampling, partial correlation |
| `threshold_analysis.R` | Decision rule: threshold of the measure above which SMOTE pays off, leave-one-dataset-out cross-validation, bootstrap intervals |
| `make_figures.R` | Figures of the simulation and real-data correlations |
| `make_heatmap.R` (`make_heatmap.py`) | Exploratory grid of the epistemic and aleatoric measures (R version with ggplot2; the Python script gives the same grid) |
| `results/` | Raw and summarised results (`real_gains.csv`, `sim_cxgain_gains.csv` and others) |

## How to reproduce

Run everything from the project root (open the `.Rproj` file in RStudio).

1. Simulation: `source("run.R")`, then `source("analiz_korelasyon.R")`.
2. Real data: `source("run_real.R")`, then `source("analiz_real.R")`.
3. Decision rule and figures: `source("threshold_analysis.R")`, `source("make_figures.R")`, `source("make_heatmap.R")`. The figures are written to `manuscript/figures/`, which is created if it does not exist.

The runs are long. The summarised results needed for steps 3 (`results/real_gains.csv` and `results/sim_cxgain_gains.csv`) are included, so the thresholds and figures can be reproduced without rerunning the experiments.

`threshold_analysis.R` and `make_heatmap.R` need only base R and `ggplot2` (the latter for `make_heatmap.R`). Package requirements of the experiments are loaded in `global.R`.

## Data

The real datasets are publicly available from the UCI Machine Learning Repository and the KEEL dataset repository. The simulated data are generated by the code in `R/data simulator/` with fixed seeds.
